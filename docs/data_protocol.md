# 正式语料的导入约定

第三阶段已导入真实测试语音与噪声，来源见 docs/data_sources.md。
本文件描述接口约定；后续训练/开发语音仍需按原始划分导入并核对来源条件。
原始音频和模型权重不自动进入 Git 仓库。

## 干净语音 JSONL

每行一个对象，必须含以下七个非空字符串字段：

| 字段 | 含义 |
| --- | --- |
| utterance_id | 全清单唯一语句 ID |
| audio_path | 绝对路径，或相对于清单文件的路径 |
| transcript | 原始文字标注；此阶段不做 CER 文本归一化 |
| speaker_id | 全数据集一致的说话人 ID |
| split | train、dev 或 test，同一说话人只属于一个集合 |
| license | 该语料的实际许可标识或条款说明 |
| source_url | 数据原始发布页面的 HTTP/HTTPS 地址 |

录音要求：单声道、16 kHz、非空且非零能量，无 NaN/Inf。需要重采样的数据应先显式
转换到派生目录，并记录转换参数和原始文件哈希，不直接改写原始文件。

将实际清单放到项目的 `data/manifests/speech.jsonl`，然后运行：

```bash
python scripts/validate_corpus.py data/manifests/speech.jsonl \
    --report results/generated/speech_inventory.json
```

报告含每条文件的实际路径、样本数、时长和 SHA256；许可声明完整不代表许可审核通过。
接口能拒绝同一说话人跨集合，以及相同字节文件改名后跨集合；不能自动识别不同编码的
同一录音或身份字段被错误标注的说话人，仍需遵守语料官方划分。

## 噪声及仿真清单

噪声需记录 noise_id、audio_path、split、license、source_url 和 sha256。
干扰语音也要纳入说话人隔离检查，不能从测试说话人抽取训练干扰语音。
点源噪声经房间 RIR 传播；扩散噪声使用明确的空间场模型，不能把独立白噪声当扩散场。

每条正式混合音的 manifest 应包含：目标/干扰/噪声来源 ID 与截取区间、场景配置、
随机种子、阵元坐标、参考麦克风、目标与实测 RT60、SNR/SIR 定义、波形长度、
所有分量路径及哈希、纯噪声校准段的位置（若使用）、信号对齐方式和统一缩放增益。
第三阶段的正式清单已保存上述来源与混合参数，纯噪声前缀为 0.6 秒；
与第二阶段的非语音诊断清单分开存储，不能混作同一套评测数据。
